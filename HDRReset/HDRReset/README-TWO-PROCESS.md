# HDRReset：单 EXE 双进程结构

## 运行方式

程序发布为一个自包含的 `HDRReset.exe`，不需要额外的 DLL 或配置文件随程序分发。

- **启动时：** 仅启动 WinForms `NotifyIcon` 托盘宿主、DDC/CI 刷新引擎和单次定时器，不创建 WPF `Application` 或窗口。
- **左键点击托盘：** 宿主通过 `Process.Start` 再启动同一个 `HDRReset.exe --ui <pipe-name>`。只有这个独立 UI 子进程进入 WPF 分支并创建主窗口。
- **进程通信：** UI 与托盘宿主通过当前用户专用的本机命名管道交换设置、刷新命令和状态快照。
- **关闭窗口右上角 X：** 只结束 WPF UI 子进程。托盘宿主、自动刷新定时器和刷新引擎继续运行。
- **重新打开窗口：** UI 子进程重新启动，并从托盘宿主请求最新状态及刷新历史。
- **界面中的“退出”：** 退出整个程序，包括托盘宿主。

## 刷新历史

最近 3 条刷新记录由托盘宿主保存在内存中。打开 UI 时宿主把历史快照发送给窗口，刷新完成后再发送更新。关闭或重新打开窗口不会清空历史；完全退出程序或重启电脑后，历史会自然消失。刷新历史不会写入硬盘，也不会生成历史日志文件。

HDR 模式、刷新间隔和语言仍按原有方式保存在 `%AppData%\HDRReset` 中；这些属于用户设置，不属于刷新历史。

## 构建单 EXE

在安装了 **.NET 8 SDK** 的 Windows 电脑上运行 `publish.bat`。输出位于 `bin\Release\net8.0-windows\win-x64\publish\HDRReset.exe`。发布参数启用 win-x64、自包含和单文件发布，并将本机运行库一并打包。

## 资源占用设计

托盘宿主不创建 WPF 窗口、不启动 UI 定时轮询线程；自动刷新使用一次性 `System.Threading.Timer`，到期后再安排下一次。UI 关闭时整个 WPF 子进程退出，由操作系统回收其托管堆、WPF 缓存、窗口句柄和相关资源，而不是尝试在同一个进程里手动清理 WPF 内存。
